## 归档标准

凡是让我停下来问了一句**"这样写在生产环境行吗"**或**"为什么这么做而不是那样做"**的代码/概念，都值得一条。

## 统一写作模板

每条记录尽量遵循以下结构——这套结构本身就是面试表达的思维框架：

1. **问题现场** —— 贴真实代码行号/场景，不适感来自哪里
2. **第一反应与直觉检验** —— 拒绝凭感觉下结论
3. **量化分析（先算账）** —— 数字表支撑，quantify before optimize
4. **真正的瓶颈/本质** —— 区分表象与根因
5. **演进路径 / 权衡对比** —— 分级方案，而非一句"上 XX"
6. **本项目决策记录** —— 为什么现在不升级 + 回头改的触发条件
7. **面试表达** —— 30 秒版话术 + 展开加分点清单

条目之间用一行 `关联 →` 交叉引用，不复制正文。
